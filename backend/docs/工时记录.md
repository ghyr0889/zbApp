# 工时记录使用与部署

## 启用

1. 更新前后端代码，重启后端。现有 `main.py` 的 `Base.metadata.create_all` 会自动创建 `work_time_sessions`、`work_time_segments` 两张新表；数据库账号需要建表权限。无需修改已有工作项表。
2. 开发环境重启前端；发布环境重新构建前端并部署产物。如果后端使用 PyInstaller，需要重新打包后端程序。
3. 登录后点击左侧“工时记录”，或在项目详情工作项列表的“本人工时”列操作。

## 操作

- “工时记录”默认打开“工作项计时”：直接列出本人全部工作项，支持搜索项目、工作包或工作项。直接在列表中开始/结束计时。
- 已完成/关闭的本人工作项仍显示在列表，但不能开始。顶部全局状态栏仅显示当前状态和跳转链接；结束操作在计时界面执行。每人同时只能保留一条未结束记录，切换工作项前需先结束当前记录。
- 刷新、切换页面、退出登录或关闭浏览器不会自动停止服务器计时。离开工作时请主动结束。
- 结束只是保存这次工时，不改变工作项完成状态；后续可再次开始同一工作项。
- “我的工时”只读，按日期、项目、工作包、工作项筛选，可分页查看，不提供开始或结束按钮。所选期间累计包含所有匹配记录，不仅当前页。
- 工时汇总页面入口暂时隐藏，包括数据看板中的入口；保留汇总接口和组件供后续使用。

## 统计与存储

- 所有时间由服务器生成，数据库使用 UTC；界面日期范围、日/月分组使用北京时间。结束日期包含当天。
- 每次开始开启一个时间段，结束关闭时间段。统计使用时间段与所选区间的交集，跨日和跨月自动分摊。
- 用户、科室及工作名称保存开始时快照；工作转办后历史工时仍归原员工，删除工作项后保留工时历史。已开启计时仍可由本人结束，转办、关闭后不能再开始新的计时。
- 用户行锁、活动记录唯一约束、请求号和版本号防止多标签页及网络重试导致重复记录。写操作失败会回滚。
- 当前计时前端每秒更新显示，约每30秒向服务器校准，返回页面时也会校准；历史记录列表同步更新。工作项列表提供刷新按钮。
- 目前仅支持开始、结束，没有手工补录、自动下班结束或工时审批。忘记结束会持续累计；报表代表手动记录时长，不等同于考勤或工作质量。

## 验证

在 backend 目录执行 `python -m unittest tests.test_work_time -v`，测试仅使用内存 SQLite，不接触业务数据库。测试覆盖连续计时、旧版暂停记录结束兼容、移除接口校验、重试、过期版本、身份鉴别、关闭/转办、删除保留、跨月统计及分页总计。MySQL 并发锁行为仍应在测试部署环境验收。

## 从旧版本升级

无需修改表结构。旧版暂停记录显示为“历史未结束”，只能结束，结束时保留原有工时，不追加暂停期间的时间。结束后可重新开始；历史已结束记录和多时间段统计保持原样。旧的 pause/resume 接口已删除，访问返回404。
